# Capstone Fantasy

A student-themed, turn-based Java RPG for Object-Oriented Programming at the University of San Jose–Recoletos. The project is in its foundation stage.

## Build and run

Install JDK 17 or newer. From the project folder, run:

```sh
sh build.sh
java -jar build/capstone-fantasy.jar
```

The game opens at 960 × 720 and can be resized, maximized, or minimized. The battlefield keeps a 16:9 aspect ratio independently of the controls below; the monster list remains overlaid on the battlefield. Other screens also retain 16:9 proportions, with black bars when needed. Use **Up/Down** and **Enter** or **Space** on the main menu. On character selection, use **Left/Right** and **Enter** or **Space** to choose or remove students; choose three, then press **Down** and **Enter** to continue. **Escape** goes back. On the campus route, use **Left/Right** to move between unlocked locations and **Enter** to start the current encounter. The first two encounters are playable; later stops are not yet available. After victory, press Enter to visit camp. At camp, use **Up/Down** to choose a student, **Enter** to use a First-Aid Kit, **E** to equip or remove the Campus Vest, **S** to save, and **C** to return to the route. The shared inventory includes the kits, one reusable vest (+4 defense), and a Campus Pass key item. From the route, **C** opens camp after the first victory.

In battle use **Up/Down** and **Enter** or **Space** to choose Attack, Ability, Item, or Defend. Each living participant's bar fills smoothly at a default rate of 3 AP per second, up to their threshold: Zack 35, Bogart 30, Charice 28, Angel 45, Library Wisps A–F 24, 26, 28, 30, 32, and 34, and Stone Sentinel 32. Stage 1 generates 1–3 monsters and stage 2 generates 2–4, including one Stone Sentinel. Planned stages 3 and 4 use 3–5 and 4–6 monsters; the final stage uses six including the boss, which occupies monster formation position 2. When a student's bar fills, that student is selected automatically. When no student is selected, a ready monster attacks automatically. Each participant's bar resets after its action. The clock pauses while a student is choosing a command or target; if multiple students are ready, they act in speed order before the clock resumes. A cursor shows the target on the battlefield: use arrow keys to move among living allies or enemies, Enter or Space to confirm, and Escape to cancel without using a turn or item. Red damage and green healing numbers rise and fade; attackers move briefly toward their target. Zack's Arcane Burst targets all living enemies. Use **Page Up/Page Down** to scroll longer battle messages. Angel can attack normally or use Healing Kiss. A graphical desktop is required.

Normal battles start with the party AP bars full. At the start of each non-boss stage battle, there is a 50% chance of an ambush: party AP starts empty, monsters start with 80% of their AP, and enemies may act first. The final boss is exempt from ambushes. The stage retains its usual enemies and advances normally after victory. Entering camp does not trigger ambushes. The AP charge rate is kept in the shared `GameSettings` configuration, with a default of 3 AP per second. A player-facing settings screen and persistent settings have not yet been implemented.

## Saving and loading

At camp, press **S** to open the save screen. Choose one of three slots with **Up/Down** and select text or binary with **Left/Right**. Press Enter to save; replacing an existing save requires a second Enter, and Esc cancels. Text and binary saves are independent files, so saving one does not update the other. The main menu's **Load Game** opens the same slot and format selector and returns a loaded game to camp. Saves are kept in `~/.capstone-fantasy/saves/` and contain the current party, levels, HP, first-aid kits, vest owner, key item, and unlocked route position. Older saves remain supported and start with the vest unequipped. Missing or invalid files show a message. This version saves at camp after either available battle.

To run the save regression check after building:

```sh
mkdir -p build/test-classes
javac -cp build/capstone-fantasy.jar -d build/test-classes tests/SaveStoreTest.java tests/RouteBattleTest.java tests/AnimationTest.java
java -cp build/capstone-fantasy.jar:build/test-classes SaveStoreTest
java -Djava.awt.headless=true -cp build/capstone-fantasy.jar:build/test-classes RouteBattleTest
java -Djava.awt.headless=true -cp build/capstone-fantasy.jar:build/test-classes AnimationTest
```

## Direction

The game is intended to be suitable for a school audience, without profanity, innuendo, sexual content, or immoral themes. Its battle layout takes inspiration from classic JRPGs and [Sara's Turn Based Battle System](https://sarajs.itch.io/saras-turn-based-battle-system); the application is being built in Java Swing. The game uses a finer, 32-bit-inspired pixel-art treatment. The battlefield and student portraits are rendered at low resolution and scaled with nearest-neighbor interpolation. The in-game shell also uses a reduced-resolution rendering layer for a consistent pixel-art appearance; native window controls remain unchanged.

## Known limitations

Two encounters and a basic camp are implemented. The campus route shows five locations, but the last three encounters are not yet playable. HP, knockouts, and remaining First-Aid Kits carry between battles; kits cannot revive knocked-out students. Saving currently captures only the available camp state. The inventory currently contains one type of consumable, one vest, and one key item; additional equipment and items are not yet implemented. The requested independent AP system and stage ambush allow enemies to act before the party, so combat does **not** satisfy the course brief's party-first turn rule; instructor approval or a compliant mode is needed. Stats and balance are provisional, sprite movement uses simple position animation rather than multiple animation frames, and the route markers and paths are drawn by the application over the campus artwork.
